Overview

In this project, I implemented Bezier curve and patch evaluation, area-weighted vertex normals, edge flips and splits, and Loop subdivision. The first two parts build smooth geometry by repeatedly interpolating control points. The mesh parts work directly with triangle connectivity. The most useful lesson was that a local mesh edit is only correct when every affected half-edge, vertex, edge, and face still points to the right neighbor; a visually plausible result alone does not guarantee that later edits will work.

Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

At a parameter t, de Casteljau's algorithm takes every adjacent pair of points and computes (1 − t)pi + tpi+1, resulting in a new, shorter list of points. Repeating this on the new list eventually results in one point.

I implemented each step of this process by looping through every adjacent pair of points and putting its interpolated point in a new list. For a fixed value of t, this one-level operation is called repeatedly until the list contains one point. This process is repeated for many values of t from 0 to 1 and the resulting points are connected to form the full curve.

Part 2: Bezier surfaces with separable 1D de Casteljau

A Bezier surface extends the idea of a Bezier curve from a sequence of control points to an array of control points. Two parameters, u and v, determine a point on the surface, analogous to how t determines a point on the curve in Part 1. For one pair of parameter values, I first run the Part 1 process at u on every row of control points. Each row reduces to one point, leaving a new column of intermediate points. I then run the same process at v on that column to obtain the final point on the surface. u, v pairs are sampled across the patch, just as t values are sampled in Part 1, to create the full surface.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

Area-weighted vertex normals provide smooth shading at each vertex, giving larger faces more weight. For each vertex, I check its neighboring faces. For non-boundary triangles, I take the cross product of the two edges starting at the vertex and add it to a running sum. The order of the two edge vectors follows a consistent winding, so the cross products point in the same outward direction. The magnitude of the cross product is double the triangle's area, so summing then normalizing these cross products yields the area weighting.

Part 4: Edge flip

To flip an edge, I replace the diagonal shared by two triangles with the diagonal that connects their opposite vertices. To do this, I first collect the shared and surrounding half-edges. I keep the same edge object instance, but change it so it represents the new diagonal between the opposite vertices. I then update the affected vertices, half-edges, edges, and faces so each refers to the correct element in the new configuration. No elements are created or removed. To make implementation easier, I named every element by its role in the two triangles, then explicitly reassigned every reference, including references whose values did not change, so none would be missed.

Part 5: Edge split

To split an edge, I insert a vertex at the midpoint of the edge. To do this, I first collect the shared and surrounding half-edges. I reuse the original edge and faces, then create one vertex, six half-edges, three edges, and two faces to turn the two triangles into four. I then update the affected vertices, half-edges, edges, and faces so each refers to the correct element in the new configuration. To make implementation easier, I named every element by its role in the four triangles, then explicitly reassigned every reference, including references whose values did not change, so none would be missed. Like Part 4, this is mostly a sequence of assignments that updates the mesh connections, but splitting is different in that it also requires creating new elements.

Part 6: Loop subdivision for mesh upsampling

Loop subdivision refines triangles of a mesh into smaller triangles, repositioning vertices based on their surrounding geometry to produce a smoother surface. I first calculate every new position from the untouched mesh, before splitting or flipping any edges. This ensures that each calculation uses the original neighbors instead of neighbors introduced by any operations. An old vertex of degree n receives (1 − n u) times its old position plus u times the sum of its neighbors, where u = 3/16 for degree 3 and 3/(8n) otherwise. For an old edge with endpoints A, B and opposite vertices C, D, the new vertex created on that edge is placed at 3/8(A + B) + 1/8(C + D). I store these positions until all of the mesh edits are complete. Next, I record which edges were present at the start, then split each of those original edges exactly once. Splitting all three edges of an original triangle creates its four smaller triangles. I flip new edges that connect one old vertex and one new vertex, replacing those diagonals with diagonals between new vertices so the four smaller triangles have the intended arrangement. Finally, I apply the stored positions to the vertices. Subdivision rounds sharp corners and edges because the position rules effectively average neighboring vertices.

For the torus below, despite the original mesh being pointy, the processed mesh is very smooth and round. The straight sides and sharp corners become increasingly rounded by every iteration of Loop subdivision. Interestingly, adding splits near a corner before subdivision creates more vertices there, so the new surface keeps a more noticeable corner instead of smoothing it away as much. This is due to how Loop subdivision works. Because Loop subdivision computes new positions from neighboring vertices, the extra nearby vertices keep the averages close to that corner instead of blending it with points farther away. The original triangulation of the cube below is uneven. A single diagonal on a face of the cube gives the two vertices touching the diagonal a greater degree than the other two. Since Loop subdivision weights depend on the neighbors of vertices, they are treated differently, and repeated subdivision makes the cube gradually asymmetric. I preprocessed the cube with splits and flips to make the faces symmetric, such that each face has two intersecting diagonals. Subdividing this produces a symmetric result.
